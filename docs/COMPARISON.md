# Comparison: upstream, the reference fork, and this implementation

Compared on 2026-09-16.

- **Upstream**: [kumoproductions/mcp-aftereffects](https://github.com/kumoproductions/mcp-aftereffects) 0.2.0, commit `11f6ca4`, MIT. 28k lines including tests.
- **Reference fork**: a public fork of that upstream by another company (0.1.1, commit `dbd1ddb`), studied for architecture and features. It keeps the upstream runtime byte-for-byte except for five files, and adds a skill corpus under its own terms.
- **This repository**: `dsrupt-after-effects-mcp` 0.1.0.

## 1. Runtime changes

|                                                            | Upstream                                           | Reference fork                                                     | Dsrupt                                                                        |
| ---------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Transport, dispatcher, mailbox, busy lock, colour pipeline | Complete                                           | Unchanged                                                          | Unchanged                                                                     |
| Server identity                                            | `mcp-aftereffects`                                 | Renamed, plus an `instructions` string pointing at the entry skill | Renamed `dsrupt-after-effects`, title, `instructions` written for this corpus |
| AE resolution                                              | Three hard-coded paths per platform + `AE_MCP_EXE` | Unchanged                                                          | Discovery module (section 6 and 7)                                            |

Verdict: the upstream runtime is mature (undo grouping, dialog suppression, consume-on-read requests, per-id mailbox, arg validation before codegen, colour-managed renders). Nothing there needed rewriting.

## 2. MCP tools added or changed

|                          | Upstream | Reference fork                           | Dsrupt                                                                                                                                                   |
| ------------------------ | -------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tools                    | 11       | 12 (`ae_get_skill`)                      | 12 (`ae_get_skill`, own implementation)                                                                                                                  |
| `ae_get_skill` behaviour | n/a      | index / entry / reference, hash-verified | Same contract, plus "did you mean" suggestions for skill and reference names, a `usage` line in the index, lazy store, `IO` vs `INVALID_ARGS` separation |

Worth recreating: yes, this is the core idea. Not copied: the reference fork's runtime changes carry no explicit license grant, so the store and tool were written from the contract, not the code.

## 3. ExtendScript / JSX

Identical in all three. No change was needed: the dispatcher already injects the mailbox path on macOS, suppresses dialogs, and guards `JSON.parse`.

## 4. Skill system

|            | Upstream | Reference fork                                                                                                      | Dsrupt                                                                                                                                 |
| ---------- | -------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Corpus     | none     | 11 skills, 35 documents, 22k words; entry skill of 1.5k words with 17 numbered references and three grouped folders | 6 skills, 18 documents, 10.9k words; entry skill of 0.9k words with 9 named references                                                 |
| Manifest   | n/a      | schemaVersion 2, per-document hashes, generated by script, Python validator                                         | version 1, per-document hashes, generated by script, Node validator that also checks tool and operation names against the built server |
| Provenance | n/a      | Archive of the original corpus retained in-repo with hashes                                                         | No third-party prose retained; independently written, enforced by a banned-term check                                                  |

Design choices kept: one entry skill that routes; references loaded one at a time; hashes so a half-edited bundle is reported. Choices dropped: numbered reference names (harder to remember than `sliders.md`), skill names that assume another product's tool set (localization, collage, character pipelines, design-tool transfer), and the "companion skills are not entry points" boilerplate repeated in every description.

## 5. Installation CLI

| ------------ | --------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CLI          | none (npx the server) | `doctor`, `config`, `install-codex`                           | `doctor`, `locate-ae`, `check-ae`, `config` (json, codex TOML, claude-code command, `--env`), `install-codex`, `install-claude-code`                                               |
| Doctor scope | n/a                   | node major, platform, entry file, dispatcher, AE path, skills | those plus npm/npx, version-manager note, PowerShell policy, install location (npx cache guard), mailbox writability and permission warnings, every AE candidate and the probe log |
| Live check   | n/a                   | none (doctor says "call ae_project_info")                     | `check-ae`: six separately reported states, refuses to boot AE unless asked                                                                                                        |

## 6. Windows / macOS detection

|                | Upstream                                                                                | Reference fork  | Dsrupt                                                                                                                                                                             |
| -------------- | --------------------------------------------------------------------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows        | `C:/Program Files/Adobe/Adobe After Effects {2026,2025,2024}/Support Files/AfterFX.exe` | Same            | Env override, running process (PowerShell `Get-Process`), all Program Files roots, registry (Adobe keys and Uninstall keys), Start Menu `.lnk` resolution, `DSRUPT_AE_SEARCH_DIRS` |
| macOS          | `/Applications/Adobe After Effects {year}/…app`                                         | Same            | Env override, running process (`ps`), `/Applications`, `~/Applications`, Spotlight bundle-id query, search dirs                                                                    |
| Node toolchain | n/a                                                                                     | node major only | node, npm, npx, manager detection (nvm, nvm-windows, Volta, fnm, n, Homebrew, installer), blocked `npm.ps1` reported as a policy issue rather than a missing npm                   |

The discovery code is behind a host interface, so both platforms are unit-tested on any OS.

## 7. AE discovery ranking

Dsrupt only: explicit override > running process > newest year, release before beta, deduplicated. The result carries every candidate and a note per probe so the doctor can show its work and the `AE_NOT_FOUND` message says what was tried.

## 8. Diagnostics / doctor

Covered in 5. One design difference: the reference fork's doctor exits non-zero when AE is not found and calls that the whole answer; Dsrupt's doctor separates "install found", "process running now" (informational), and defers the live test to `check-ae`.

## 11. Packaging

Upstream publishes to npm and the MCP Registry with a release workflow. The reference fork publishes to npm under its own name. Dsrupt: private package, no registry, install from Git; upstream release scripts, `server.json` and artwork removed; `UPSTREAM.md` and the LICENSE notice retained.

## 12. Anything else useful

- The reference fork's README rule "only report connected after a successful live response, and distinguish missing app, permission denial, startup timeout and a working MCP with disconnected AE" is a good rule. It became `check-ae` and the `ae-mcp-realities` skill.
- Its evaluation questions (ten read-only Q&A pairs over the corpus) are a cheap regression idea for skill edits; not reproduced yet, noted for later.
- Its Blender package and design-tool transfer skill are out of scope.

## Not adopted, on purpose

- A Python dependency for skill validation (Node does it).
- Skill descriptions that repeat the same 30-word disclaimer; the index must stay small.
- Media-generation defaults naming specific vendor models; Dsrupt's `media.md` points at the Dsrupt connector when present and otherwise asks.
- The 17-reference entry skill. Nine references cover the same technical ground; character pipelines, localization and collage are left for later skills if needed.
